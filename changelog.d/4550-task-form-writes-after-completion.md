# Workflow tasks write their records only once the task is completed, and complete only once (#4550, #4560)

Six workflow task forms used to create or change records while the answer was still being prepared, before the task was marked completed: the consent request (with its audit entry), the logged prospect, the new test training, the trial case and promoted player on an admit, the trial-case decision and prospect archival on a team-offer answer, and the decision of a trial-group review. If completing the task then failed, the record stayed behind while the task was still open, and the next attempt created a second one. Those writes now happen in a separate completion step that runs in one database transaction with marking the task completed. Either both land, or neither does and the task stays open to try again. The ids of what was written still land in the task's stored answer, and the template's follow-up steps, which run after the commit, still see them. A task is now completed only once, on every route. A second submit, whether from a stale tab or racing the first, leaves the answer on record and its follow-ups as they were. A parent who clicks the confirmation link twice at once gets the same answer both times. Completing a task once still creates exactly one record, as before.
