# Workflow tasks write their records only once the task is completed (#4550)

Six workflow task forms used to create or change records while the answer was still being prepared, before the task was marked completed: the consent request (with its audit entry), the logged prospect, the new test training, the trial case and promoted player on an admit, the trial-case decision and prospect archival on a team-offer answer, and the decision of a trial-group review. If completing the task then failed, the record stayed behind while the task was still open, and the next attempt created a second one. Those writes now happen in a separate completion step that the task engine runs only after the task row is marked completed. The ids of what was written still land in the task's stored answer, and the template's follow-up steps still see them. A task that is already completed is no longer written for a second time when it is submitted again from a stale tab. Completing a task once still creates exactly one record, as before.
