# Report Studio, phase 1: block registry, block engine and the report-blocks routes (#4568)

Bump: minor

The server side of Report Studio (epic #4564). A new Report Studio module registers blocks, each of which reads one shared report query or the analytics engine and returns data, never HTML. `GET /report-blocks` lists the blocks a reader may place, with typed option schemas. `POST /report-blocks/{key}/preview` returns one block's data for a subject and a period, and writes nothing. Three blocks ship as proof: playing time per player (the minutes query the team monthly report uses), attendance per week, and your own question (one declared measure of one analytics fact, optionally broken down by one declared dimension). The subject is checked on every call, an external audience never gets a breakdown by player, and the limits (60 players, 396 days, 5,000 rows with a truncation flag) are enforced. The Studio is a Pro feature (402 otherwise) and is switched off by default. The analytics engine now takes the reader's scope as SQL on every query: a team-scoped reader reads only their teams' rows, trial decisions and prospects are for academy-wide readers only, journey events follow the reader's visibility levels, and the result cache is keyed by that scope. The evaluations fact's Team now means the team at evaluation time (the activity's team, else the team history on the evaluation date, else "No team"), and the evaluations and attendance facts gain a declared distinct-players measure and, for attendance, a week dimension.
