# Reading a player's parents over REST is audited like the profile card (#4361)

`GET players/{id}/parents` returned guardian names and e-mail addresses without leaving a trace, while the same read on the player's Parents · Guardians card has written an audit row since #4253. The route now reads through the same `GuardianContacts` service and writes one `player.guardian_contacts_viewed` row naming the reader and the player, with the surface `rest_players_parents` and the count. A refused or empty read writes nothing, and the audit payload never holds a name or an e-mail address. The response keeps its shape; a link to an account that no longer exists is no longer listed.
