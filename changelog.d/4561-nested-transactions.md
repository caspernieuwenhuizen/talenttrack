# One transaction helper, so a write inside another no longer commits it early (#4561)

MySQL has no nested transactions: opening one while another is open silently commits the first. Archiving a player, the permanent-delete cascades, saved views, VCT sessions, the backup restores and imports and the authorization seed import each opened their own. When one of them ran inside another, the outer work was committed at that moment, and a later failure could no longer undo it. The concrete case was a trial-group review that ends in a final decline: it archives the player in the middle of completing the task, so a failure after the archive left a half-completed task. All of them now go through one helper, which opens the transaction on the outside and takes a savepoint for every level inside it. An inner failure undoes only its own writes, and the outer transaction still decides. Messages and file deletions that wait for a commit now wait for the outermost one. Each of these operations behaves exactly as before when it runs on its own.
