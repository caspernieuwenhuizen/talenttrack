# Analytics: a filter or field that does not exist is refused, never ignored (#4860)

The analytics engine used to skip a filter or grouping that named a field its data did not have, and answered for every row instead: a filter on a field that was renamed or never there gave a plausible number for the wrong players. It now refuses such a field everywhere. The explorer and its CSV and PDF exports say "This refers to a field that no longer exists" and name it. A Report Studio block that names a missing field shows "This block refers to a field that no longer exists" in its place, for the builder and every reader, while the rest of the report reads as usual; such a block cannot be saved, and its preview answers `400 unknown_dimension`. A KPI card that cannot be narrowed to the player, team or activity it sits on is no longer shown with the academy-wide figure, and a scheduled KPI report whose KPI names a missing field is not sent, with the reason on the schedule. A deliberately renamed field keeps working: the data declares the old name as an alias of the new one. An empty "one of" filter now means no rows rather than all rows.
