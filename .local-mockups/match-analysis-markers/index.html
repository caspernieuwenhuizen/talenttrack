Player marker — four stacked radios, four ways out

Same fourteen-player squad in every variant, so the comparison is about how each one scales. All four keep the same three markers and the same stored data (players[ID][marker] + note + phase) — only the interaction changes. D and E are live: click them.

One player as it renders now — six rows before the note field starts, times fourteen.

Thijs

A — Segmented control

Four equal segments in one pill, full width on mobile. Every state is readable without tapping, which is what makes it safe for a control most rows never leave.

    Trade-off: the Dutch labels wrap to two lines at 360px. Fixable by shortening the vocabulary (Eruit / Verwacht / Tekort) — a copy decision, not a CSS one. Fourteen of these is still a long page.

    B — Three chips, no fourth state

    "Niet genoemd" stops being an option and becomes the absence of one. Three targets instead of four; clearing is a small link that appears once something is set.

      Trade-off: full words fit, but the chips wrap at 360px and "how do I undo this" is something the coach has to discover.

      C — Glyph row per player

      Four 44px cells (— ▲ ● ▼) on the same line as the name. Still a form per player, but the tightest version of one.

        Trade-off: a glyph has to be learned. ▲/▼ read as up/down, which is the right metaphor, but first use needs the tooltip or the state line to teach it.

        D — Tally sheet: tap a name to tag it — live, click the names

        The squad is a grid of names, not a stack of forms. Tapping a name cycles it — → ▲ → ● → ▼ → —, and only the players you tagged grow a note field, underneath. Marking three players out of fourteen costs three taps and shows exactly three text inputs.

          Toelichting

            Nog niemand genoemd — dat mag.

            Why this one: the whole squad stays visible, so nobody is quietly skipped — the reason the roster is listed at all — but the form only exists where the coach has something to say. Fourteen players fit on one phone screen.
            Trade-off: cycling has to be taught (the legend does it), and it needs JS. Without JS it degrades to today's rendering — every player, every field — so nothing is lost, it is just less pleasant.

            F — Tally grid, direct choice — live, click the names

            D's layout with C's directness: the squad is still a grid of names, but tapping one opens a three-way picker instead of cycling. Always two taps, in any direction, with the options named in words — nothing to learn and nothing to cycle past.

                What it fixes: D's two weak points — the cycle you have to learn, and "below par" costing three taps — without giving up the compact grid. Screen readers get a normal menu of three named options rather than a button whose meaning changes each press.
